차량 하드웨어 시뮬레이션 및 UI 상태 반응 테스트 리포트

VHAL 하드웨어 센서(탑승자 감지, 주행 속도, HAL 프로퍼티)의 변경 사항을 adb shell am broadcast로 주입하고, Jetpack Compose 설정 화면에서 Item.isVisible, ValueWithState.isEnabled, ValueWithState.isVisible, ValueWithState.isSelected가 실시간으로 재구성(Recomposition)되는 결과를 검증한 리포트 및 수동 테스트 가이드입니다.

시뮬레이션 아키텍처 및 반응 파이프라인

개발자나 QA 엔지니어가 물리적 차량 장비 없이도 터미널 명령어 한 줄로 모든 하드웨어 상태와 UI 엣지 케이스를 테스트할 수 있도록 설계되었습니다.

Step 1. ADB Broadcast
HardwareSimulationReceiver
com.example.carsettings.SIMULATE_HARDWARE Intent 액션을 수신하여 파라미터 파싱
Step 2. HAL Simulation Hub
VehicleHardwareSimulator
인메모리 VHAL 스토리지 및 센서별 StateFlow(탑승자 감지, 주행 락아웃, 옵션 숨김) 값 갱신
Step 3. Reactive ViewModel
ChoiceHardwareItemViewModel
combine()을 통해 ValueWithState(isSelected, isEnabled, isVisible) 리스트를 원자적으로 방출
Step 4. Compose UI
GenericSettingsActivity
LocalItemViewModelRegistry를 구독하여 Item 전체 또는 개별 Option 칩이 즉각 리컴포지션
[사전 준비] 시트 설정 화면 실행 명령어 (PowerShell / CMD / Bash 공용)
adb shell am start -n com.example.lifecycleapp/.GenericSettingsActivity -a com.example.carsettings.seat.OPEN
시나리오별 테스트 검증 결과 및 수동 재현 가이드
시나리오 1. 탑승자 감지 센서 연동 (Item isVisible 동적 제어)
조수석 탑승자가 하차하면 동승석 열선 Item 전체가 화면에서 사라지고, 탑승 시 다시 나타납니다.
Item.isVisible / isVisibleFlow
[1-A] 미착석 시뮬레이션 (동승석 시트 열선 숨김)
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --ez passenger_present false
[1-B] 재착석 시뮬레이션 (동승석 시트 열선 복원)
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --ez passenger_present true
기준 화면 (착석 상태) Baseline
동승석 시트 열선 노출: 4번째 항목으로 조수석 열선 조절 행(꺼짐/1단/2단/3단)이 정상 표시됩니다.
미착석 시뮬레이션 결과 Item Hidden
Item 완전 제거: 동승석 시트 열선이 사라지고, '이지 억세스'와 '4방향 럼버' 항목이 상단으로 이동합니다.
재착석 시뮬레이션 결과 Item Restored
즉시 복원: 탑승자가 감지되는 즉시 동승석 시트 열선 행이 원래 위치로 부드럽게 복원됩니다.
시나리오 2. 주행 중 마사지 락아웃 (ValueWithState isEnabled 비활성화)
차량 주행(속도 > 0 km/h) 시 운전자 안전을 위해 위험 마사지 모드가 Grayed-out 비활성화되며 터치가 차단됩니다.
ValueWithState.isEnabled
[2-A] 주행 속도 60km/h 락아웃 시뮬레이션
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --ei speed 60
[2-B] 정차(속도 0km/h) 락아웃 해제 시뮬레이션
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --ei speed 0
정차 상태 (전체 모드 활성) Speed = 0
전체 옵션 활성: '에르고 모션 마사지'의 골반/웨이브, 허리 집중, 전신 스트레칭이 모두 선명하게 선택 가능한 상태입니다.
주행 중 상태 (위험 옵션 잠금) Speed = 60 km/h
시각적 Grayed-Out & 상호작용 차단: '꺼짐'만 선택 가능하며, 골반/웨이브, 허리 집중, 전신 스트레칭 칩의 텍스트가 회색으로 비활성화됩니다.
시나리오 3. 특정 옵션 동적 숨김 (ValueWithState isVisible)
차량 트림별 미지원 기능이나 특정 국가 법규에 따라 특정 옵션(예: '전신 스트레칭')만 칩 목록에서 제거합니다.
ValueWithState.isVisible
[3-A] '전신 스트레칭(STRETCH)' 옵션 숨김 시뮬레이션
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --es item seat_massage --es hide_options STRETCH
[3-B] 모든 옵션 숨김 해제
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --es item seat_massage --es hide_options none
기준 상태 (4개 칩 노출) 4 Options
전체 옵션 표시: [꺼짐], [골반/웨이브], [허리 집중], [전신 스트레칭] 4개의 FilterChip이 배치되어 있습니다.
STRETCH 숨김 결과 (3개 칩 노출) 3 Options
단일 옵션 완전 제거: [전신 스트레칭] 칩만 레이아웃에서 제거되고, 나머지 3개 칩이 너비에 맞춰 균등하게 리사이징됩니다.
시나리오 4. 하드웨어 스위치 / VHAL 외부 조작 (ValueWithState isSelected)
센터페시아의 물리적 버튼 조작이나 백그라운드 VHAL 상태 변경이 UI의 세그먼트 버튼 및 라벨에 실시간 반영됩니다.
ValueWithState.isSelected / selectedValue
[4-A] 운전석 시트 열선 3단 설정 시뮬레이션 (따옴표 이스케이프 주의)
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --es item driver_seat_heat --es value '\"LEVEL 3\"'
[4-B] 운전석 시트 열선 꺼짐(OFF)으로 복원
adb shell am broadcast -a com.example.carsettings.SIMULATE_HARDWARE -p com.example.lifecycleapp --es item driver_seat_heat --es value OFF
초기 상태 (열선 꺼짐) Initial: OFF
초기 꺼짐 선택: 'Current: 꺼짐' 및 [꺼짐] 세그먼트 버튼이 보라색 배경으로 선택되어 있습니다.
외부 3단 주입 결과 Mutated: LEVEL 3
원자적 즉시 갱신: [3단] 세그먼트 버튼이 보라색(#6750A4)으로 반전되고, 상단 상태 텍스트가 'Current: 3단'으로 동기화됩니다.

다른 카테고리(도어 및 잠금)에서도 개별 토글 스위치 항목의 `isVisibleFlow`가 유연하게 작동하는지 검증합니다.
UiToggleItem.isVisible

[5-B] '주행 시 자동 도어 잠금(auto_lock)' 토글 복원
